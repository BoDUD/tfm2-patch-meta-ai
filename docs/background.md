# 背景：旧 Mod 为什么在新版游戏里不工作

yudra 的「Win-Rate Ban/Pick AI + Champion Tiers」（`draft_winrate_penalty` 0.5.0，创意工坊 3741141600）
已停止更新。它已经是稳定版 API 的原生 Mod（2026-09-17 为游戏 0.6.0 编译，要求的 ABI 等级是 1），
所以不是"0.6 起不再支持旧版 classic SDK"这个原因。分析它的 DLL 后找到这些问题：

1. **增量扫描记的是"列表下标"而不是记录 id。** 它把"往回补读到 MatchReplay id 列表的第几个"存成下标，
   下一轮直接拿这个下标去取列表元素（带越界检查，越界就 panic，位置 `src/lib.rs:479`）。
   列表变短的情况很常见：
   - 同一次游戏里读了另一个存档，或开了新档；
   - 游戏清理了旧回放。

   panic 发生时它正持有统计数据的锁，锁因此中毒。之后每次重建一看到锁中毒就直接返回，于是梯队和
   ban/pick 修正在这一次游戏里再也不更新（或者一直是空的）。SDK 会接住这个 panic，所以游戏不会提示
   Mod 出错，只是它悄悄地不起作用了。
2. **换存档时不清空统计。** 上一个存档"读到的最大 id"会让新存档的记录被跳过，两个存档的数据也会混在一起。
3. **用子串搜索代替 JSON 解析。** 它在文本里找 `"champion":"`、`"position":"`、`"version":"`、
   `"played":true`、`"is_buff":`：
   - 嵌套数据里同名的键也会被算进去；
   - 游戏数据格式一变，就会悄悄得到错的数据或者什么都没有。
4. **游戏 0.6.2（9 月 29 日）改了自动平衡补丁的加强/削弱名单。** 它读补丁公告的那部分依赖旧名单。
5. **写梯队失败没有后备，也没有提示。** 游戏的数据校验一旦拒绝整个梯队对象，就什么都没写进去，玩家也看不到原因。

## Patch Meta AI 怎么避免这些问题

| 问题 | 做法 |
|---|---|
| 1 | 扫描器只记已读的记录 **id**（`src/scan.rs`），列表变短、换掉都只是"少了几条"；所有锁都容忍中毒，回调里不做任何未经检查的下标访问 |
| 2 | 按"球队 id + 队名"识别存档，换存档或回到标题画面就清空重来（`src/client.rs`） |
| 3 | 真正解析 JSON（`src/records.rs`）：先按 0.6 的结构读，读不到就在整个文档里找对应字段；只认球员条目里的 `champion`，跳过 ban 位等嵌套数据；每个存档第一次读到的数据格式写进 `diag.log` |
| 4 | 补丁公告兼容几种结构（`src/patchnotes.rs`）；只用"加强行数 − 削弱行数"的方向 |
| 5 | 整体写入被拒时，先去掉 NoTier 再写，再逐个英雄写；结果和梯队字段原来的样子写进 `diag.log`；服务端回执确认后才算写入成功，游戏内换日时还会检查梯队有没有被改回去（`src/server.rs`、`src/client.rs`） |

模型、设置格式和美术都是新设计（见 README 的"原理"），没有使用原 Mod 的代码、文字或图片；上面的
分析只用来确认旧 Mod 的失效原因。
